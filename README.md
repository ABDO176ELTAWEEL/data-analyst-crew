#  Data Analyst Crew (CrewAI + Gemini)

Upload a CSV, ask a question in plain English, and a team of four AI agents analyzes the data, double-checks the numbers, draws a chart, and writes a short report.

Built with **CrewAI**, **Google Gemini**, **Pandas**, **Matplotlib**, and **Gradio**. The repo grows step by step: from a single agent with one tool to a guarded 4-agent web app.

## Features

- **Natural-language questions** about any CSV file (no SQL or pandas needed).
- **Four specialized agents** that cooperate in sequence and check each other's work.
- **Real computed numbers:** the agents write and run pandas code instead of guessing.
- **Independent review:** a second agent recomputes every number and questions the assumptions.
- **Automatic chart** generated with Matplotlib next to the report.
- **Guardrails** against runaway loops, unsafe code, unverified numbers, and API failures.

##  How It Works

```text
CSV + question
      │
      ▼
  Analyst ──▶ Reviewer ──▶ Visualizer ──▶ Writer
  (pandas)    (recompute    (one chart)   (short report,
               + assumptions               verified numbers
               check)                      only)
      │
      ▼
Markdown report + chart
```

| Agent | Role | Tools |
| :--- | :--- | :--- |
| **Senior Data Analyst** | Inspects the data, writes pandas code, reports numbers and assumptions | `csv_summary`, `run_pandas_code` |
| **Data Reviewer** | Recomputes the numbers independently and gives a `CONFIRMED` / `WRONG` verdict | `run_pandas_code` |
| **Data Visualizer** | Draws one chart that matches the verified findings (skips it if a chart would not help) | `make_chart` |
| **Report Writer** | Writes a short report using only the verified numbers | `none` |

##  Setup & Installation

1. **Clone the repository**
   ```bash
   git clone https://github.com/<your-username>/<your-repo-name>.git
   cd <your-repo-name>
   ```

2. **Create and activate a Python 3.12 virtual environment**
   - **Windows (PowerShell):**
     ```powershell
     py -3.12 -m venv .venv
     .\.venv\Scripts\Activate.ps1
     ```
     > If activation is blocked, run `Set-ExecutionPolicy -Scope Process Bypass` first and try again.
   - **macOS / Linux:**
     ```bash
     python3.12 -m venv .venv
     source .venv/bin/activate
     ```

3. **Install dependencies**
   ```bash
   pip install --upgrade pip
   pip install -r requirements.txt
   ```

4. **Configure your API key**
   ```bash
   cp .env.example .env   # Windows: copy .env.example .env
   ```
   Then edit `.env`:
   ```env
   GEMINI_API_KEY=your_actual_gemini_api_key
   ```
   > **Never commit your `.env` file.** It is already listed in `.gitignore`.

##  Usage

- **Web app (recommended):**
  ```bash
  python app.py
  ```
  Open the local URL printed in the terminal (usually `http://127.0.0.1:7860`), upload a CSV, type a question, and click **Analyze**. A run can take a couple of minutes because four agents work one after another.

- **Single-agent script:**
  ```bash
  python first_agent.py
  ```

- **Multi-agent CLI script (writes `report.md`):**
  ```bash
  python three_agent.py
  ```

###  Tip: be specific in your question

Questions like *"Which age group has the highest spending score?"* leave the grouping up to the agent, so different runs may use different age bins and give different answers. Specify the grouping yourself:

> `Which age group (18-25, 26-35, 36-50, 51+) has the highest average spending score?`

##  Example Output

**Question:** *Which age group has the highest average spending score?* *(sample run on the Mall Customers dataset)*

```markdown
# Report: Spending Score by Age Group

**Highest Spending Group**
The age group with the highest average spending score is the 18-30 category, which has an average spending score of 58.58.

**Assumptions**
* Age was segmented into four categories: 18-30, 31-45, 46-60, and 61+.
* The mean was used to represent the average spending score for each group.
* The binning method was adjusted to ensure all data points, including the minimum age of 18, were included in the calculation.
```

> Results can vary between runs, since LLM output is not deterministic.

##  Guardrails

Agents can make mistakes, loop forever, or invent numbers, so the project wraps them in several layers of protection:

| Risk | Protection |
| :--- | :--- |
| **Endless loops and high cost** | `max_iter`, `max_execution_time`, and `max_retry_limit` on every agent; `max_rpm` on the crew |
| **Unsafe generated code** | A blocklist checks the code before `exec()` (no `os`, `subprocess`, file writes, `eval`, dunder access, etc.) |
| **Invented numbers in the report** | A task guardrail rejects any number in the report that does not appear in the reviewer's verified output, and asks the writer to fix it |
| **Wrong or hidden assumptions** | The analyst must list its assumptions and the reviewer must evaluate them |
| **API failures (`503`, rate limits)** | Retry with exponential backoff |
| **Bad user input** | File size limit (`5 MB`), question length limit (`300` characters), CSV readability check |
| **Shared state between requests** | The crew is built per request; each run uses its own data path and temporary chart folder |

---

##  Limitations & Security

Please read this before using or deploying the project:

- **`exec()` is not a real sandbox.** The blocklist catches common mistakes but can be bypassed. Run the app locally only, do not use `share=True`, and do not expose it to untrusted users. For anything public, run the code execution in an isolated environment such as a Docker container.
- **Your data leaves your machine.** The CSV content (column names, sample rows, query results) is sent to the Gemini API. Do not upload sensitive or private data.
- **The numbers guardrail checks numbers, not claims.** A report can still contain an unsupported conclusion (for example, calling something a "trend") even when every number is correct.
- **Charts are not cross-checked.** The visualizer writes its own code, so always compare the chart with the report.
- **Results are not fully reproducible.** Different runs can choose different assumptions, especially for open-ended questions.
- **Free-tier limits apply.** You may see `503` (model busy) or `429` (rate limit) errors. Wait a bit and try again.

##  Configuration

The model is set in the `LLM(...)` call near the top of each script:

```python
llm = LLM(
    model="gemini/gemini-3.1-flash-lite",
    api_key=os.getenv("GEMINI_API_KEY"),
)
```

The `gemini/` prefix tells CrewAI which provider to use. You can switch to another model by changing the name (see the models page in Google AI Studio) or to another provider by changing the prefix and the matching API key.

##  Troubleshooting

| Problem | Fix |
| :--- | :--- |
| `metadata-generation-failed` / `numpy` fails to install | Use **Python 3.12** in a fresh virtual environment, not 3.14 |
| `OPENAI_API_KEY is required for model ...` | The model name is missing the `gemini/` prefix, or the API key was passed as the model name |
| `503 UNAVAILABLE` | The Gemini model is busy; retry later or switch to another (for example a `lite`) model |
| Key not found | Make sure the file is named `.env` (not `.env.txt`), sits next to the script, and `load_dotenv()` runs before `LLM(...)` |
| Imports shown as errors in the editor | Select the `.venv` interpreter in your IDE |
